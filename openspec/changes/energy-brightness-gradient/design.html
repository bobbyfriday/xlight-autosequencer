OpenSpec design · energy-brightness-gradient

Design: energy-continuous brightness gradient

Rendered brightness does not track section energy (measured r = −0.59). Give brightness the same continuous-energy treatment the other visual dimensions already have, via a bounded palette-value multiplier — without re-introducing the dim-section floor PR #125 fixed.

Goal

Make rendered brightness rise monotonically with section energy_score so a higher-energy section reads brighter than a lower-energy one, closing the one energy dimension that is still quantized away while the others (speed, color boldness, sparkle, density) already scale continuously.

Evidence

Render-grounded FSEQ diagnostics on two songs against Rob's real 81-prop layout. Brightness = mean of lit channels per section.

Across sections, energy↔brightness correlation r = −0.59 (Nostalgic Piano, real librosa sections + RMS energy). The same flat/scrambled pattern appeared on Maple Leaf Rag.

The inversion is essentially coincidental: energy reaches brightness only through the 3-bucket energy_to_mood; every body section lands in "structural", so brightness is governed downstream by harmonic tension (unrelated to energy), not by the energy arc.

Approach

This generator has no Brightness parameter — brightness is the HSV value (V) of the palette colors. The single existing per-section brightness lever is adjust_palette_brightness(palette, tension) in chord_colors.py, which scales V by a tension-derived multiplier.

Add a parallel, energy-derived multiplier composed with it:

def energy_brightness_multiplier(energy_score: int) -> float:
    # energy 0 → 0.80, energy 100 → 1.20 (linear, clamped)
    return 0.80 + max(0, min(100, energy_score)) / 100.0 * 0.40

# at per-section palette finalization:
final_V = base_V × tension_mult × energy_mult   # each clamped to ≤ 100

Energy continues to drive tier selection via mood_tier (unchanged). This adds an orthogonal brightness gradient within whatever tier set the mood selects.

Floor safety: the multiplier minimum is 0.80 — it never reduces brightness below 80% of the post-#125 value, so it cannot re-introduce the dim-section regression. The gradient only adds headroom at the high-energy end.

Alternatives considered

Re-bucket / widen energy_to_mood

Add more mood tiers so energy resolves more finely. Rejected: mood_tier drives which tiers fire — changing it perturbs placement structure, group counts, the rotation plan, and every tier-coverage test, a large blast radius to fix a brightness-scaling gap. The palette-V multiplier is orthogonal and leaves placement untouched.

Also scale speed / color / boldness harder with energy

Originally raised in conversation. Rejected as already done: compute_duration_target (speed, ×0.7–1.3), restrain_palette (color count, 2 + energy//33), and compute_music_sparkles all scale continuously with energy today. Duplicating that would over-correct. This change closes only the brightness gap. Consequence for verification: high-energy sections are already faster/busier/more colorful, so the test must be multi-dimensional to avoid over-correcting brightness.

Regression surface

  • energy_to_mood — untouched. Callers: energy.py:84, plan.py:419. Mood path unchanged.
  • _TIER_BRIGHTNESS — untouched. Only a palette-selector flag at effect_placer.py:702, not a multiplier.
  • adjust_palette_brightness — call site gains a second multiplier factor; signature unchanged, so its own callers/tests are unaffected.
  • New energy_brightness_multiplier — pure function, new symbol, no existing callers; covered by a new unit test.

Golden/baseline impact: existing generator golden tests and microscope baselines will shift (palette V changes per section). These are human-blessed checkpoints — they get re-captured only after the render loop confirms the change is an improvement, not auto-refreshed.

Historical echoes

.wolf/buglog.json: 0 matches for energy/brightness/mood/tier. .wolf/cerebrum.md Do-Not-Repeat: no matching entries.

PR #125 (dim-section-real-cause) — directly adjacent and important. It found that low-energy structural sections rendered pathologically dim because the rotation dedup fallback kept sparse Single-Strand variants; it fixed the floor via dense-fill variant preference + relaxed density brackets. Its own smoking gun (N2 energy 49 bright vs section 8 energy 50 dim — same energy, different surviving variants) confirms this design's root cause: within the structural band, brightness today is governed by variant/density accident, not energy. #125 explicitly did not add an energy gradient and stayed within the structural band. This change is complementary: it adds the gradient #125 omitted, and its 0.80 floor is constructed specifically to not undo #125's floor fix.

Verification plan

Via tools/render_panel — multi-dimensional, because speed/density/color already carry energy:

  • Energy↔brightness correlation on Nostalgic Piano: −0.59 → ≥ +0.5.
  • Floor preserved: minimum per-section brightness ≥ pre-change minimum (guards #125's fix).
  • lit_mean and placement counts unchanged (tier selection untouched).
  • Before/after contact sheet of highest- and lowest-energy sections — high-energy section visibly brighter.
  • New unit test for energy_brightness_multiplier (monotonic, bounded 0.80–1.20, clamps out-of-range input).

Revert criteria: correlation fails to go positive, or the brightness floor drops.

Out of scope

  • Changing energy_to_mood buckets or tier selection.
  • Emitting an xLights Brightness / value-curve parameter.
  • Re-tuning #125's density brackets or dense-fill set.
  • Confirming the real vamp analyzer also clusters energy into one mood band — likely true and motivating, but not required for this change, whose defect is structural in the code regardless of input source.
